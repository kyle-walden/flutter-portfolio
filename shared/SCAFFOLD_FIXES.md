# Scaffold Script Bug Fixes

## Issues Identified and Resolved

### 1. ❌ Dependencies in Wrong Section (CRITICAL)
**Problem**: The scaffold script was inserting dependencies into `dev_dependencies:` section instead of `dependencies:`.

**Impact**: 
- All runtime dependencies (provider, http, hive, etc.) were incorrectly placed in dev_dependencies
- Caused "depend_on_referenced_packages" errors for every service file
- Projects generated by the script would fail to build properly

**Root Cause**: The `sed` command was using `/^dev_dependencies:/r` which inserts AFTER the line, not before.

**Fix**: Replaced `sed` with `awk` to properly insert dependencies BEFORE the `dev_dependencies:` line:
```bash
awk '
    /^dev_dependencies:/ {
        # Read and print the additions file
        while ((getline line < "pubspec_additions.yaml") > 0) {
            print line
        }
        close("pubspec_additions.yaml")
    }
    { print }
' pubspec.yaml > pubspec.yaml.tmp
```

**Files Changed**:
- `flutter-portfolio/shared/scaffold-flutter-project.sh` (line ~814)

### 2. ❌ HomeProvider Method Signature Mismatch
**Problem**: Generated `HomeProvider` called repository methods incorrectly:
- `_repo.fetchData()` - missing required `key` parameter
- `_repo.saveData(newData)` - method doesn't exist (should be `saveLocalData`)

**Impact**:
- Compilation errors in generated projects
- "not_enough_positional_arguments" error
- "undefined_method" error

**Root Cause**: Disconnect between the repository interface and the provider using it.

**Fix**: Updated HomeProvider template to match repository methods:
```dart
Future<void> loadData({String key = 'default'}) async {
  isLoading = true;
  notifyListeners();
  data = await _repo.fetchData(key);  // Added key parameter
  isLoading = false;
  notifyListeners();
}

Future<void> saveData(Map<String, dynamic> newData, {String key = 'default'}) async {
  await _repo.saveLocalData(key, newData);  // Changed to saveLocalData
  data = newData;
  notifyListeners();
}
```

**Files Changed**:
- `flutter-portfolio/shared/scaffold-flutter-project.sh` (line ~627-648)
- `personal_website/lib/features/home/state/home_provider.dart` (fixed manually)

---

### 3. ⚠️ Unused Field in Portfolio Example
**Problem**: `BookingRepo` in portfolio example project had unused `_fs` field warning.

**Impact**: 
- Minor - just a warning
- Code smell indicating incomplete implementation

**Root Cause**: Repository methods are stubbed (for portfolio demo purposes) but constructor still accepts/stores the service.

**Fix**: Commented out the field and updated constructor to accept but not store:
```dart
class BookingRepo {
  // final FirestoreService _fs;  // Unused in stubbed implementation
  BookingRepo(FirestoreService fs);  // Accept but don't store for now
```

**Files Changed**:
- `flutter-portfolio/projects/vendor0/flutter_app/lib/features/booking_management/repo/booking_repo.dart`

## Expected Firebase Service Errors

The following errors are **EXPECTED** and **CORRECT**:
- Firebase service files import packages that are commented out in pubspec.yaml
- Services are provided as templates to be used after Firebase configuration
- Users must uncomment Firebase packages and run `flutterfire configure` before using these services

**This is by design** - we don't want to force Firebase on every project.
